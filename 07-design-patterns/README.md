 07 - Design Patterns

Patterns are most valuable when you can explain when to use them, what problem they solve, and how they trade off with alternatives.

## Notes

- [SOLID principles](solid.md) — single responsibility, open/closed, Liskov, interface segregation, dependency inversion
- [Creational patterns](creational.md) — factory, builder, singleton, prototype
- [Structural patterns](structural.md) — adapter, decorator, facade, composite
- [Behavioral patterns](behavioral.md) — observer, strategy, template method, command

## Interview approach

- Name the pattern clearly.
- Explain the design problem it solves.
- Give one real-world example.
- Mention trade-offs and alternatives.
